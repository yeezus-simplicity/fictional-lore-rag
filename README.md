# 多模态混合检索系统：结构化-非结构化联合推理

> 当一次查询同时需要**结构化精确计算**和**语义理解**时，系统如何决策"查哪边"、如何融合两边的结果、如何处理两者之间的冲突。

**状态：📋 立项定稿（v0.2）** — 架构与数据规范已确定，尚未开始编码。

---

## 问题定义

多数 RAG 项目处理的是纯文本语料。本项目处理**异构知识源**：同一批知识中，数值型事实适合 SQL 精确计算，描述性内容适合向量检索，而真实查询往往同时需要两者。

核心问题不是"如何做向量检索"，而是：

1. **意图路由** —— 判断本次查询该走哪条路径，或两条都要走
2. **结果融合** —— 两侧结果如何合并
3. **冲突消解** —— 两侧结论矛盾时如何仲裁（如结构化记录"等级 E"，文本描述"时停 5 秒"）
4. **脏数据处理** —— 「缺失」「未知」「不适用」「无限」「条件值」是五种不同语义，不可一律当缺失

这套机制在企业知识库（HR 政策 + 报销规则 + 合同条款）完全同构。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 切块 | 自实现，**招式级语义切分**（不用固定长度） |
| Embedding | bge-m3 fp16（568M，2.2GB） |
| 向量库 | pgvector |
| 重排 | bge-reranker-v2-m3（0.6B） |
| 生成 | Qwen2.5-1.5B Q4（主力）· 7B（对照） |
| 服务层 | **C++20**（epoll · 线程池 · SSE） |
| 编排 | LangGraph（Agent 能力） |
| 监控 | Prometheus + Grafana |
| 评测 | 自建评测集 + RAGAS 交叉验证 |

### 硬件约束

本机 **RTX 4060 Laptop · 8GB 显存**。这是硬约束，也是实验变量：

| 用途 | 显存 |
| --- | --- |
| bge-m3 fp16 常驻 | 2.2 GB |
| bge-reranker-v2-m3 错峰 | 1.1 GB |
| Qwen2.5-1.5B Q4 常驻 | 1.2 GB |
| KV Cache 预留（8K） | 2.0 GB |
| 余量 | 1.5 GB |

**fp16 而非 fp32**：实测 bge-m3 fp32 需 3.5GB，fp16 仅 2.2GB，检索任务精度损失几乎可忽略。省下的 1.3GB 决定对照模型能否装入。

**Ada 架构红利**：Compute Capability 8.9 支持 FP8，可做 FP8 / FP16 / INT4 三档精度对比。

## 核心设计决策（实验假设，非既定结论）

| 编号 | 决策点 |
| --- | --- |
| D1 | 切块策略：固定长度 / 递归字符 / 语义切分 |
| D2 | 检索模式：纯向量 / BM25 / 混合 RRF |
| D3 | Rerank 开关与深度 |
| D4 | 混合权重 α 扫描 |
| **D5** | **冲突消解：加权 RRF / 规则优先 / 置信度仲裁 / 二次验证** |
| **D6** | **模型规模与精度：1.5B FP16 / INT4 / FP8 · 7B Q4** |
| D7 | 语义缓存阈值与误命中权衡 |
| **D8** | **脏数据编码：异常值当缺失 / 五类语义分类** |
| **D9** | **检索路由：规则 / 小模型 / 混合** |

> D5 / D8 / D9 是本项目区别于普通 RAG 的三个核心实验。

## 数据规范摘要

**等级映射**：`None=0, E=1, D=2, C=3, B=4, A=5`

**五类异常值必须区分**：

| 原始值 | 语义 | 存储 |
| --- | --- | --- |
| `∅` | 数据源该格未填 | NULL, `EMPTY_SLOT` |
| `?` | 有值但不确定 | NULL, `UNKNOWN` |
| `N/A` | 不适用 | NULL, `NOT_APPLICABLE` |
| `∞` | 无限 | NULL, `INFINITE` |
| `※依成熟度而定` | 条件值 | 按状态拆多行 |

> `∅` 与 `?` 的区别是本项目最关键的数据设计：前者是"缺失"，后者是"未知"。

**结构化数据不进向量库** —— 数值走 SQL，文本走向量，工具选型按数据性质决定。

完整规范见 [`docs/数据规范.md`](docs/数据规范.md)。
