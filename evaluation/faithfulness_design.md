"""
忠实度指标设计（M6）。

★★ 核心立场：指标设计优先于实现。

M3 的教训：两次「指标与目标脱钩」都是**判分方式**的问题，
不是算法的问题。所以这里先把指标定义清楚，再写代码。

---

## 一、要回答什么问题

M3 用了 Oracle 生成（直接从 gold 拿答案），这**隔离了生成能力**，
导致 M3 期间所有实验都无法回答：

> 检索到的证据，LLM 能不能基于它答对？

M6 要回答的核心问题：**答案是否忠实于检索到的证据。**

---

## 二、为什么 1.5B 也能可靠评测

一个常见误解：小模型不可靠，所以评测不可信。

**事实相反**：评测「是否忠实」比评测「是否聪明」简单得多。
忠实度是**二元的、可机械核对的** —— 答案里的每个事实断言能否在证据中找到出处。

1.5B 模型完全能胜任「复述证据」这件事。评测它做不好，
只能说明**证据组织得不好**（比如块太大、包含太多无关内容），
这本身就是要测的信号。

---

## 三、忠实度的三个层次

按「能自动核对的程度」分层，**从易到难**：

### L1 句级溯源（Fully Automatic，最可靠）
把答案切成句，每句检查是否能匹配到某个证据块。

- **实现**：token 覆盖率 + 最长公共子串
- **可靠性**：高（纯字符串操作，无 LLM 参与）
- **局限**：字面改写会被误判

### L2 断言抽取 + 逐条核对（半自动，中等可靠）
从答案里抽出「事实断言」，检查每条是否被证据支持。

- **实现**：抽取数值/实体 → 在证据中查找
- **可靠性**：中（只对特定类型的事实有效，如「射程是 E」）
- **优势**：能定位**具体哪一句**是幻觉

### L3 LLM-as-judge（Automatic，可信度依赖评审模型）
用 LLM 判断答案是否被证据支持。

- **实现**：rubric 提示词 + 逐条打分
- **可靠性**：**依赖评审模型，且有自我偏好偏差**
- ★ 本项目**不用 LLM 评 LLM** 作为主指标：
  1.5B 模型做评审员本身不可靠；
  若换成更强的模型评审，又引入「评审模型的评测」问题。

---

## 四、本项目的指标设计

### 主指标：L1 + L2 组合（零 LLM 参与）

| 指标 | 定义 | 可靠性 | 回答什么 |
|---|---|---|---|
| **溯源覆盖率** | 答案中能匹配到证据的 token 占比 | 高 | 答案有多少是「抄」来的 |
| **数值正确率** | 答案里的数值型断言被证据支持的比例 | 高 | 有没有编造数字 |
| **实体一致率** | 答案提到的替身名都在证据里 | 高 | 有没有张冠李戴 |
| **矛盾率** | 答案与证据冲突的比例 | 高 | 有没有说出反面的话 |

### ★ 关键设计：不能只看这些指标

**高溯源覆盖率 ≠ 好答案。** 一个只抄证据里最不重要一句的答案，
溯源覆盖率 100%，但毫无价值。

因此配一个**反向指标**：

| 反向指标 | 定义 | 防止什么 |
|---|---|---|
| **证据利用率** | 答案覆盖了证据的多少 | 防止「只抄一句」 |
| **空洞回答率** | 答案是否只是「无法确定」 | 防止「安全但无用」 |

---

## 五、对照组设计（关键）

★★ **不做对照组，任何忠实度数字都没有意义。**

需要四个配置：

| 配置 | 证据 | 目的 |
|---|---|---|
| **A. 生成式（有证据）** | Top-K 检索结果 | 本项目主指标 |
| **B. 抽取式（M5 现状）** | 检索结果 | 忠实度上界（100%） |
| C. 生成式（无证据） | 空| **关键对照**：模型编造程度 |
| D. 乱码证据 | 随机打乱的证据 | 敏感度检验 |

**C 最重要**：如果「无证据生成」的忠实度和「有证据生成」差不多，
说明**证据根本没起作用**，RAG 只是一层装饰。

**D 用来检验指标的敏感度**：如果给乱码证据，指标仍然很高，
说明指标测不出幻觉，是无效指标。

## 六、必须先自检（按 M3 的4 问）

在实现之前先回答：

| 自检项 | 回答 |
|---|---|
| 1. gold 粒度与配置匹配吗？ | 忠实度的 gold 是「证据块」，与检索配置无关 ✓ |
| 2. 多配置量纲一致吗？ | 四个配置都用同一套指标 ✓ |
| 3. 「改进」是否不需改系统代码？ | 指标只读答案与证据，不改系统 ✓ |
| 4. 负向结果是否违反常识？ | 待观察；若 C 组忠实度≈A 组，则指标或系统有问题 |

## 七、预期结果与判读

| 现象 | 含义 |
|---|---|
| A 组溯源覆盖 0.7~0.9 | 正常（1.5B 模型应有改写） |
| B 组 = 1.0 | 预期（抽取式直接抄） |
| **C 组 < A 组 显著** | RAG 有效 ✓ |
| **C 组 ≈ A 组** | ⚠️ **RAG 失效，证据没起作用** |
| D 组接近 C 组 | 指标对证据质量敏感 ✓ |
| D 组接近 A 组 | ⚠️ **指标无效，测不出证据质量差异** |

## 八、已知局限（必须写进报告）

1. **字面改写会被误判**：LLM 把「E 级」写成「等级为E」，token 匹配可能漏
   → 部分用 L2 的数值抽取补救
2. **只覆盖可机械核对的忠实度**，不覆盖「是否回答了正确的问题」
3. **1.5B 模型的生成质量有限**，绝对值不代表 SOTA 水平，
   只用于**验证 RAG 链路是否打通**
4. **样本量**需足够大才有统计意义

## 九、★ 实现阶段的 11 轮修错（比设计本身更有价值）

指标设计得再漂亮，实现出来照样全是坑。以下每一轮都是**被真实数据打脸**才发现的。

| 轮次 | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | `"a"` 在 `"rated"` 里匹配上 | 子串匹配 | 先切词建集合再判断 |
| 2 ★★ | 乱码证据下溯源率仍 1.00 | **词袋模型下打乱顺序不改变 token 集合** | 加 2-gram 连续短语 |
| 3 | `破坏力不是A级` → 维度=「破坏力不」 | 否定词被吞进维度名 | 先按否定切分 |
| 4 ★ | numeric 全为 0 | 题型（T4）没有数值断言 | 混采 T1/T7；显示区分 None 与 0 |
| 5 ★ | `射程是 5 米` 全判错 | 证据是**带单位物理量**，我只比等级字母 | 分「等级」「物理量」两条路径 |
| 6 ★★ | `300米` 截成 `3` | `\d(?:\.\d)?` 只匹配 1–2 位 | 改`\d+` |
| 7 ★★★ | `A=5` 算成 `E` | 自己写 `abcde[4-n]`，n=5 时索引 -1 **绕回** | 复用 `encode.py` 的权威映射 |
| 8 ★★ | `速度是 A` 判对 | ±20 词窗口把**相邻维度**的值圈进来 | 最小窗口 + 遇下个维度词即停 |
| 9 ★ | 维度抽成「力等级定」 | 正则 `[一-鿿]{2,4}?` 切碎 | 放弃捕获组，改「就近回溯」 |
| 10 ★ | 序列号「1.」被当断言 | 列表序号污染 | `_is_list_index()` 过滤 |
| 11 ★ | `Diavolo` 的 D 当成等级 | 等级字母未要求独立出现 | 加 `(?<![A-Za-z])` 词边界 |

### ★★ 贯穿全部 11 轮的一个模式

**所有 bug 都表现为「指标太宽松，什么都能判对」，没有一个表现为「报错」或「明显异常」。**

具体表现：
- 轮 2：乱码证据也能拿满分 → **看起来还很漂亮**
- 轮 7：`A=5` 算成 `E` → 数值「有值」，看不出错
- 轮 8：速度借用破坏力的值 → 判为「正确」
- 轮 10：序号当断言 → 只是**略微**拉低分数

**如果只跑一遍看总分，这11 个bug 里有 8 个根本发现不了。**

→ **必须逐条打印中间结果**（`details`、`candidates`、`维度映射`），
让每个判定都能被单独检验。

### ★ 三条可迁移的规则

| 规则 | 出处 | 说明 |
|---|---|---|
| **映射表必须复用数据层定义** | 轮 7 | 自己推导 `abcde[4-n]` 越界。`encode.py` 里已有 `GRADE_TO_VALUE` |
| **判定要「独立出现」而非子串包含** | 轮 1、11 | `a`∈`rated`、`D`∈`Diavolo` 是同一类错误 |
| **邻近窗口必须有边界** | 轮 8 | 「维度词后N 个词」里的 N 要有停止条件，否则会串到邻居 |

### ★ 与 M3 / M4 的教训同源

| 阶段 | 症状 | 病根 |
|---|---|---|
| M3 | 指标与量纲脱钩 | 判分方式与目标不匹配 |
| M4 | 偏向强度是小样本假象 | 统计量脱离样本量解读 |
| **M6** | **指标能力与题型不匹配 + 实现细节错** | **指标本身的 bug** |

**三类都是同一件事：指标不是「算出来的」，是「设计 + 实现」两层的产物，
两层都可能与意图脱钩。**

而验证手段只能是：**用真实数据跑，逐条打印中间量，而不是只看总分。**
