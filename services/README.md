# services/ 服务层

M4：冲突消解 + 查询路由。

## 快速开始

```bash
# 冲突消解自测（含消融对比 + 路由测试）
python services/conflict_resolver.py

# M4 评测（路由对比 + 消解消融 + 敏感性分析）
python evaluation/run_m4_eval.py

# 把消解结果写回数据库
python services/apply_resolutions.py --dry-run   # 先看
python services/apply_resolutions.py
```

## 文件

| 文件 | 作用 |
|---|---|
| `conflict_resolver.py` | 消解策略 + 路由器（可解释） |
| `apply_resolutions.py` | 消解结果写回数据库 + 记日志 |

## 消解策略

| 策略 | 适用 | 依据 |
|---|---|---|
| `prefer_primary` | 主源权威 | jojowiki 是官方设定集 |
| `prefer_consensus` | 两镜像独立给相同值 | 交叉验证，置信 0.95 |
| `split_by_form` | 分歧源于形态未消解 | 两者都可成立 |
| `keep_unknown` | 主源标 `?` | **不臆测** |

## ★ 路由的三轮迭代

| 轮次 | 准确率 | 修的问题 |
|---|---|---|
| 初版 | 0.8864 | T5 修好，T2/T3 崩 |
| + 实体表补全 | 0.9773 | 小节名误判 + 变体名漏判 |
| + 实体抽取 + 变体检测 | **1.0000** | — |

## 踩坑

| 坑 | 现象 | 修法 |
| --- | --- | --- |
| **已知实体只有替身名** | 部名/使用者名被误判为编造，T2 掉 20%、T3 掉 40% | 实体集 = 替身 + 部名 + 使用者 |
| **小节名全大写被当实体** | `THE STAND` `DRAGONS` | 过滤全大写串 |
| **变体名漏判** | `King Crimson Red` 含已知实体被放过 | 变体检测：后缀 ≥3 字符且不在已知集 |
| **`value is None` 判语义** | 9 条「? vs 具体值」被错标为「缺失」 | 回看 `category` 区分「没有」与「不知道」 |
| **refine 精度估算** | — | 未用 embedding 精排，检索指标见 M3 报告 |

## ★ 满分结果的自检

M4 路由拿到 1.0000，**按 M3 教训必须先怀疑自己**：

```
把已知实体表清空 → 准确率仍 0.9943
```

说明规则本身在工作，不是在背实体表。**排除过拟合。**

但满分应理解为「**在本评测集上饱和**」，不是「问题解决」——
评测集问句是程序化生成的，真实输入更口语化。
