## 2. 五个问题与修法

### 2.1 ★★ 中文名脚本「改进过但从未重跑」（第五次）

`fetch_zh_characters.py` 在 M21 / M70 / M72 期间被反复改进：
rowspan 解析**连改两版**、全角标点处理、`{{nihongo}}` 模板第二数据源……
**但产物一直停在 154 个角色。**

后果：**主角级角色全部查不到中文名**——

```
乔尼·乔斯达（SBR 主角）     ✗
乔鲁诺·乔巴拿（第5部主角）   ✗
布罗诺·布加拉提（第5部核心） ✗
空条徐伦（第6部主角）       ✗
杰洛·齐贝林（SBR 核心）     ✗
```

重跑后 **154 → 219（+65）**，全部补上。

> ★ 这是「上游脚本改进、下游产物没重算」的**第五次**：
> M68 没进抓取队列 → M70 抓取名单有盲区 → M71 rendered 快照没重算 →
> M72 篇章块没重算 → **M73 中文名没重算**。
> 五次的共同根：**产物看着完全正常，所以没人会去重跑它。**
> → 本轮把「角色中文名覆盖」也加进了 `--check` 闸门（见 §4）。

### 2.2 质检：过滤「解析错位」产生的假别名

重跑后新增的候选里混着**别人的名字**。两个典型：

```
whitesnake_s_unknown_victim → ['桑达·麦奎恩','蜜拉休','史波兹·马克思',
                               '维瓦诺·魏斯伍德','白蛇']
    ↑ 5 个名字，其中 4 个各自属于**别的角色**，
      还有一个「白蛇」是**替身名**本身。
      源站某行把一串人名写在同一个「本体」单元格里，顿号拆分后全挂上了。

d_i_s_c_o        → 含「巧克力迪斯可」（替身名，非人名）
donatello_versus → 含「恋人」（Lovers，Steely Dan 的替身名）
```

**两条规则**（都遵循项目口径「宁可少给一个，不给错的一个」）：

| 规则 | 判据 | 命中 |
|---|---|---|
| ① | 一个角色拆出 **>3** 个候选名 → 整条丢弃 | 1 条 |
| ② | 候选名是**已知替身中文名** → 移除该名 | 2 条 |

**★★ 刻意不做的一条规则（写下来防止以后又加回去）★★**

曾经想加第三条：「候选名 X 是另一个角色名字 O 的真子串 → 移除」，
用意是抓 `caravan_serai → ['理发厅老板康','波鲁那雷夫']` 这种串行错位
（「波鲁那雷夫」 ⊂ 「J·P·波鲁那雷夫」）。

**实测误杀率 60%（3/5）**，全是**同名系列**：

```
george_joestar_i       「乔治·乔斯达」 ⊂ 「乔治·乔斯达三世」
norisuke_higashikata_i 「东方宪助」     ⊂ 「第四代东方宪助」
pocoloco               「波克洛克」     ⊂ 同名变体
```

这三条**都是真名**（乔治一世就叫「乔治·乔斯达」）。
子串关系在同名系列里是**正常**的，无法与串行错位区分：

- 「J·P·波鲁那雷夫」→「波鲁那雷夫」是**前缀缩写**
- 「乔治·乔斯达三世」→「乔治·乔斯达」是**代际后缀**

形态完全一样。

→ **代价不对等**：为修 1 条错位（用户搜「波鲁那雷夫」命中一个理发厅老板），
而删掉 3 条真名（用户搜「东方宪助」直接搜不到）—— **净亏**。
宁可留那 1 条已知残余。

另有第 3 条保护：唯一的名字被判成替身名时**保留原样**
（`pocoloco` →「波克洛克」是**人**的中文名，只是维基把本体名填进了
「替身中文名」列，导致它进了替身名表；按规则②删掉就是误杀）。

### 2.3 ★ 简称：用户不打「布罗诺·布加拉提」

中文维基给的是**全名带间隔号**，而用户几乎不这么打：

```
「布加拉提的替身是什么」→ 查不到（库里只有「布罗诺·布加拉提」）
「东方仗助的替身是什么」→ 能查到（它本来就没间隔号）
```

→ 同一个「XX 的替身」句式，能不能答取决于**名字里有没有间隔号**，
这个差异对用户完全不可见。

**修法**：对**含间隔号**的名字拆出简称，但只收**唯一归属**的：

| | 数量 | 处理 |
|---|---|---|
| 可拆出的简称 | 144 | — |
| **唯一归属**（收） | **134** | 布加拉提 / 西撒 / 乔尼 / 乔鲁诺 / 丹尼尔… |
| **有歧义**（不收） | 10 | 齐贝林（5 个角色）/ 乔斯达（12 个）/ 达比（2 个）/ 布兰度（3 个） |

★ 歧义的**一律不收** —— 这些是**姓氏**，收了只会让「齐贝林的替身」
必然答成某一位。宁可漏一个简称，也不引入一个必然答错的名字。

★ 只拆**含间隔号**的名字：日式无间隔号的名字（「空条徐伦」）**不拆** ——
拆成「空条」/「徐伦」要分姓与名，中文与日文的分界规则不同
（「东方仗助」姓东方、「广濑康一」拆哪边？），误拆会把「东方」这种
**跨角色姓氏**当成某人的别名 → 抢匹配。

### 2.4 ★★ 同一概念两份规则（第五次），这次一并合流

简称加好了，但**实测仍查不到** —— 因为「角色名有哪些写法」在库里
**有两份**：

| 来源 | 内容 | 被谁用 |
|---|---|---|
| `characters_ext.json` 的 `name_zh` | **只有全名** | `characters.match()`、`known_characters` |
| `aliases.build_char_alias_table()` | 全名 **+ 简称** | 路由别名表 |

→ 只修别名表没用：Router 的 `known_characters` 来自 ext
（抽不到「布加拉提」→ 判成「没有识别出具体角色」），
`characters.match()` 也用 ext（抽到也匹配不上）。

这是「同一个概念维护两份」的**第五次**
（M69 词表 / M70 抓取名单 / M71 出场记录口径 / M72 角色数 / 本次角色名写法）。

**修法**：两处都并上别名表，**单一来源**：

- `api/main.py`：`known_characters = ext 的名字 ∪ 别名表`（1120 个写法）
- `characters.load()`：`by_name` 并上别名表（只收 `by_id` 里真实存在的 id）

### 2.5 ★「X 是谁的替身」被误判成未知人名

`ZH_PERSON_TMPL = re.compile(r"([一-鿿]{2,4})的替身")` 是 `finditer`，
会在**任意位置**找匹配。实测：

```
「白金之星是谁的替身」
  位置 0-2 尝试失败（第 5 字是「是」不是「的」）
  → 从第 3 个字起匹配成功 → name = "之星是谁"
  → 不在 STOP 词里 → 判成**未知人名** → 直接 abstain
```

后果：**最基础的问法之一**（「某替身是谁的」）得到
「该问题涉及的数据集中不存在」的拒答；
而只写「白金之星是谁的」（少一个「替身」）反而能答 ——
**同一个意思，两种写法一个能答一个拒答。**

**修法**：加 `OWNER_ASK`，匹配**完整**的「是谁的替身 / 谁的替身」
→ 命中即跳过未知人名判定（主体必然是替身，用户在问它的持有者）。

★ 刻意**不放宽**成「只认 `是谁的`」：那会把 T6 守门用例
「甘道夫的替身是什么」也放过。只认**完整**的「是谁的替身」。

### 2.6 出场章节的 NL 入口（M71 的最后一公里）

M71 建了 `stand_appearances`（**4902 条**）与 `/appearances/{stand_id}` 端点，
但**自然语言没有入口**：

```
「白金之星在哪些章节出场」→ 语义检索 → 返回一段原文介绍
                            （而库里有结构化的章节列表）
```

**修法**：新增 `appearance` 意图 + `_appearance` 执行器。

判据必须同时含「出场语义」与「章节/话数」：

- 只写「出场」会把「黄金体验的能力出场效果」之类误收
- 只写「章节」会抢走「第 4 部有哪些章节」这类篇章问句

口径：
- **漫画（manga）/ 动画（anime）分开列**，不混成一张表
- **`cover`（仅封面出场）不计入** —— 那不是「出场」，列进去会让
  「出场章节」变成用户不认的东西（实测 Star Platinum 有 1160 条 cover）
- 每条回传**源站原文**（`raw`，形如 `"Stone Ocean Chapter 12: The Visitor, Part 2"`），
  因为章号是**部内相对**的（第 6–9 部从 1 起，M71 的发现），
  单给 `ch12` 用户对不上漫画

## 4. 闸门

`--check` 新增 1 项（共 **31 项**）：

```
数据.角色中文名覆盖 = 219
```

进闸门的理由：这个数字**停在 154 停了很久而没人发现** ——
因为输出看着完全正常（角色答案只是少了中文名）。
闸门是唯一能在「没人主动去看」时发现它的东西。
