# 环境说明

> 本文记录**开发时实际踩到的环境坑**（多为受限网络 / 代理环境），
> 供复现者参考。本机路径已泛化。

## 解释器

Python **3.11+** 均可（开发用 3.13）。建议独立虚拟环境：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -i https://pypi.org/simple -r requirements.txt
```

> ★ 用「装有依赖的那个解释器」跑脚本。系统里常有多个 Python，
> 裸 `python` 可能指向一个没装第三方包的版本。

## ★ pip 索引源：必须用官方 PyPI

**问题**：pip 默认配置为清华镜像（`pypi.tuna.tsinghua.edu.cn`），在本环境下手工`pip install` 会失败：

```
ERROR: Could not find a version that satisfies the requirement requests (from versions: none)
```

**根因**：该镜像返回的索引页里，wheel 包链接指向 `../../packages/...` 相对路径，
且不含 `files.pythonhosted.org`。pip 在受限环境下无法解析该跳转，报"无可用版本"。

**解决**：改用官方源。可临时指定，或写入 pip 配置（`pip config set global.index-url
https://pypi.org/simple`）。

```ini
[global]
index-url = https://pypi.org/simple
```

**若遇到同类失败**，按此顺序排查：
```bash
# 1. 显式指定官方源（最直接）
python -m pip install -i https://pypi.org/simple <pkg>

# 2. 排除缓存
python -m pip install --no-cache-dir <pkg>
```

## 已知环境坑

| 坑 | 说明 |
| --- | --- |
| **PowerShell 工具静默返回空** | `Get-CimInstance` 等命令无输出，判读结果不可靠。查硬件用 Bash + `nvidia-smi` |
| **pip 编译慢** | `psycopg2-binary` 装一次约 7 分钟。建议后台运行（`run_in_background`），分批装，别用短 timeout |
| **NBSP 字符** | 部分 CSV 含 `0xa0`，`utf-8` 解码报错。读取用 `utf-8 → utf-8-sig → latin-1` 回退 |

## 模型下载（2026-10-03 补充）

### HuggingFace 沙箱访问方案

| 站点 | 状态 |
| --- | --- |
| `huggingface.co` | ❌ 502（代理拦截） |
| `hf-mirror.com` | ✅ 200 |

**★ 关键坑**：`huggingface_hub.snapshot_download` 配`HF_ENDPOINT=https://hf-mirror.com`
能"下载成功"，但**文件是 0 字节**——库对 302 重定向的跟随逻辑在此环境失效。
`curl -L` 手动跟随则完全正常。

**对策**：用 `retrieval/fetch_model.py`（urllib 手动跟随 302）而非 huggingface_hub。

```bash
cd retrieval
python fetch_model.py --file-set weights_only
```

### 权重文件名不通用

`BAAI/bge-m3` 仓库**没有 `model.safetensors`**，只有 `pytorch_model.bin`。
不要假设 safetensors 是标准格式——**先查仓库实际文件列表**：

```bash
curl -sSL "https://hf-mirror.com/api/models/BAAI/bge-m3" | python -c "..."
```

该仓库另有 ONNX 版本（`onnx/model.onnx`），体积更小、CPU 更友好，
若 GPU 不可用可作备选。

### 大文件下载

2.3GB 权重在慢速网络下需10+ 分钟。**必须**：
- 放后台运行（`run_in_background`）
- `timeout` 设到 1800秒以上
- 下载器支持断点判断（已下过的文件跳过）

## PyTorch 安装记录

| 尝试 | 结果 |
| --- | --- |
| `torch>=2.5` + cu124 源 | ❌ 5分钟超时 |
| `torch` CPU 版（pypi） | ✅ 2.14.1+cpu，耗时 21 分钟 |
| `--force-reinstall --no-deps` + cu124 |后台运行中 |

**注意**：pip 默认清华镜像会导致 wheel 解析失败（见上文），必须显式指定源。

**fp16 说明**：cpu 设备上不要用 fp16（极慢且数值不稳定），
`dense.py` 的 `DenseEmbedder` 已按 device 自动选择精度。
