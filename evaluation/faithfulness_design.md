"""
忠实度指标设计（M6）。

★★ 核心立场：指标设计优先于实现。

M3 的教训：两次「指标与目标脱钩」都是**判分方式**的问题，
不是算法的问题。所以这里先把指标定义清楚，再写代码。

---

## 一、要回答什么问题

M3 用了 Oracle 生成（直接从 gold 拿答案），这**隔离了生成能力**，
导致 M3 期间所有实验都无法回答：

> 检索到的证据，LLM 能不能基于它答对？

M6 要回答的核心问题：**答案是否忠实于检索到的证据。**

---

## 二、为什么 1.5B 也能可靠评测

一个常见误解：小模型不可靠，所以评测不可信。

**事实相反**：评测「是否忠实」比评测「是否聪明」简单得多。
忠实度是**二元的、可机械核对的** —— 答案里的每个事实断言能否在证据中找到出处。

1.5B 模型完全能胜任「复述证据」这件事。评测它做不好，
只能说明**证据组织得不好**（比如块太大、包含太多无关内容），
这本身就是要测的信号。

---

## 三、忠实度的三个层次

按「能自动核对的程度」分层，**从易到难**：

### L1 句级溯源（Fully Automatic，最可靠）
把答案切成句，每句检查是否能匹配到某个证据块。

- **实现**：token 覆盖率 + 最长公共子串
- **可靠性**：高（纯字符串操作，无 LLM 参与）
- **局限**：字面改写会被误判

### L2 断言抽取 + 逐条核对（半自动，中等可靠）
从答案里抽出「事实断言」，检查每条是否被证据支持。

- **实现**：抽取数值/实体 → 在证据中查找
- **可靠性**：中（只对特定类型的事实有效，如「射程是 E」）
- **优势**：能定位**具体哪一句**是幻觉

### L3 LLM-as-judge（Automatic，可信度依赖评审模型）
用 LLM 判断答案是否被证据支持。

- **实现**：rubric 提示词 + 逐条打分
- **可靠性**：**依赖评审模型，且有自我偏好偏差**
- ★ 本项目**不用 LLM 评 LLM** 作为主指标：
  1.5B 模型做评审员本身不可靠；
  若换成更强的模型评审，又引入「评审模型的评测」问题。

---

## 四、本项目的指标设计

### 主指标：L1 + L2 组合（零 LLM 参与）

| 指标 | 定义 | 可靠性 | 回答什么 |
|---|---|---|---|
| **溯源覆盖率** | 答案中能匹配到证据的 token 占比 | 高 | 答案有多少是「抄」来的 |
| **数值正确率** | 答案里的数值型断言被证据支持的比例 | 高 | 有没有编造数字 |
| **实体一致率** | 答案提到的替身名都在证据里 | 高 | 有没有张冠李戴 |
| **矛盾率** | 答案与证据冲突的比例 | 高 | 有没有说出反面的话 |

### ★ 关键设计：不能只看这些指标

**高溯源覆盖率 ≠ 好答案。** 一个只抄证据里最不重要一句的答案，
溯源覆盖率 100%，但毫无价值。

因此配一个**反向指标**：

| 反向指标 | 定义 | 防止什么 |
|---|---|---|
| **证据利用率** | 答案覆盖了证据的多少 | 防止「只抄一句」 |
| **空洞回答率** | 答案是否只是「无法确定」 | 防止「安全但无用」 |

---

## 五、对照组设计（关键）

★★ **不做对照组，任何忠实度数字都没有意义。**

需要四个配置：

| 配置 | 证据 | 目的 |
|---|---|---|
| **A. 生成式（有证据）** | Top-K 检索结果 | 本项目主指标 |
| **B. 抽取式（M5 现状）** | 检索结果 | 忠实度上界（100%） |
| C. 生成式（无证据） | 空| **关键对照**：模型编造程度 |
| D. 乱码证据 | 随机打乱的证据 | 敏感度检验 |

**C 最重要**：如果「无证据生成」的忠实度和「有证据生成」差不多，
说明**证据根本没起作用**，RAG 只是一层装饰。

**D 用来检验指标的敏感度**：如果给乱码证据，指标仍然很高，
说明指标测不出幻觉，是无效指标。

在实现之前先回答：

| 自检项 | 回答 |

| 2. 多配置量纲一致吗？ | 四个配置都用同一套指标 ✓ |
| 3. 「改进」是否不需改系统代码？ | 指标只读答案与证据，不改系统 ✓ |
| 4. 负向结果是否违反常识？ | 待观察；若 C 组忠实度≈A 组，则指标或系统有问题 |

## 七、预期结果与判读

| 现象 | 含义 |
|---|---|
| A 组溯源覆盖 0.7~0.9 | 正常（1.5B 模型应有改写） |
| B 组 = 1.0 | 预期（抽取式直接抄） |
| **C 组 < A 组 显著** | RAG 有效 ✓ |
| **C 组 ≈ A 组** | ⚠️ **RAG 失效，证据没起作用** |
| D 组接近 C 组 | 指标对证据质量敏感 ✓ |

## 八、已知局限（必须写进报告）

1. **字面改写会被误判**：LLM 把「E 级」写成「等级为E」，token 匹配可能漏
   → 部分用 L2 的数值抽取补救
2. **只覆盖可机械核对的忠实度**，不覆盖「是否回答了正确的问题」
3. **1.5B 模型的生成质量有限**，绝对值不代表 SOTA 水平，
   只用于**验证 RAG 链路是否打通**
4. **样本量**需足够大才有统计意义

## 九、★ 实现阶段的 11 轮修错（比设计本身更有价值）

指标设计得再漂亮，实现出来照样全是坑。以下每一轮都是**被真实数据打脸**才发现的。

| 轮次 | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | `"a"` 在 `"rated"` 里匹配上 | 子串匹配 | 先切词建集合再判断 |
| 2 ★★ | 乱码证据下溯源率仍 1.00 | **词袋模型下打乱顺序不改变 token 集合** | 加 2-gram 连续短语 |
| 3 | `破坏力不是A级` → 维度=「破坏力不」 | 否定词被吞进维度名 | 先按否定切分 |
| 4 ★ | numeric 全为 0 | 题型（T4）没有数值断言 | 混采 T1/T7；显示区分 None 与 0 |
| 5 ★ | `射程是 5 米` 全判错 | 证据是**带单位物理量**，我只比等级字母 | 分「等级」「物理量」两条路径 |
| 6 ★★ | `300米` 截成 `3` | `\d(?:\.\d)?` 只匹配 1–2 位 | 改`\d+` |
| 7 ★★★ | `A=5` 算成 `E` | 自己写 `abcde[4-n]`，n=5 时索引 -1 **绕回** | 复用 `encode.py` 的权威映射 |
| 8 ★★ | `速度是 A` 判对 | ±20 词窗口把**相邻维度**的值圈进来 | 最小窗口 + 遇下个维度词即停 |
| 9 ★ | 维度抽成「力等级定」 | 正则 `[一-鿿]{2,4}?` 切碎 | 放弃捕获组，改「就近回溯」 |
| 10 ★ | 序列号「1.」被当断言 | 列表序号污染 | `_is_list_index()` 过滤 |
| 11 ★ | `Diavolo` 的 D 当成等级 | 等级字母未要求独立出现 | 加 `(?<![A-Za-z])` 词边界 |

### ★★ 贯穿全部 11 轮的一个模式

**所有 bug 都表现为「指标太宽松，什么都能判对」，没有一个表现为「报错」或「明显异常」。**

具体表现：
- 轮 2：乱码证据也能拿满分 → **看起来还很漂亮**
- 轮 7：`A=5` 算成 `E` → 数值「有值」，看不出错
- 轮 8：速度借用破坏力的值 → 判为「正确」
- 轮 10：序号当断言 → 只是**略微**拉低分数

**如果只跑一遍看总分，这11 个bug 里有 8 个根本发现不了。**

→ **必须逐条打印中间结果**（`details`、`candidates`、`维度映射`），
让每个判定都能被单独检验。

### ★ 三条可迁移的规则

| 规则 | 出处 | 说明 |
|---|---|---|
| **映射表必须复用数据层定义** | 轮 7 | 自己推导 `abcde[4-n]` 越界。`encode.py` 里已有 `GRADE_TO_VALUE` |
| **判定要「独立出现」而非子串包含** | 轮 1、11 | `a`∈`rated`、`D`∈`Diavolo` 是同一类错误 |
| **邻近窗口必须有边界** | 轮 8 | 「维度词后N 个词」里的 N 要有停止条件，否则会串到邻居 |

### ★ 与 M3 / M4 的教训同源

| 阶段 | 症状 | 病根 |
|---|---|---|
| M3 | 指标与量纲脱钩 | 判分方式与目标不匹配 |
| M4 | 偏向强度是小样本假象 | 统计量脱离样本量解读 |
| **M6** | **指标能力与题型不匹配 + 实现细节错** | **指标本身的 bug** |

**三类都是同一件事：指标不是「算出来的」，是「设计 + 实现」两层的产物，
两层都可能与意图脱钩。**

而验证手段只能是：**用真实数据跑，逐条打印中间量，而不是只看总分。**

## 十、★ M7 的发现：单指标必然偏向一方（比"用哪个指标"更重要）

M7 用生成层重做 M3 的「块大小」实验时，发现了一个比M3 更一般的规律。

### 10.1 两个指标是**镜像偏差**

| 阶段 | 用的指标 | 偏好 | 最优解 | 病根|
|---|---|---|---|---|
| M3 | precision / nDCG | **大块** | 2048（全部 1.0000） | 大块把答案装进去 → precision 必然高 |
| M7 第一版 | 证据利用率 | **小块** | 256（0.2133） | 比例指标天然偏好小块（分母小） |

**两个指标各自只测了一个维度，方向恰好相反。**

### 10.2 关键：利用率是「比例」，被用字数才是「信息量」

| 块长 | 证据字数 | 利用率（比例） | **被用字数（绝对量）** |
|---|---|---|---|
| 256 | 1026 | **0.2133** ↓最高 | 219 |
| 2048 | 4902 | 0.1310 | **642** ↑最高 |

证据字数涨 4.8 倍，利用率只降 39% → **绝对被用字数涨 2.9 倍**。

**大块确实让答案引用了更多内容**，只是"念的比例"变低。

→ **同一个数字（利用率）在两个故事里扮演不同角色**，
   单看它必然得出片面结论。

### 10.3 ★ 完整权衡需要四类指标

| 类别 | 指标 | 偏好 | 回答什么 |
|---|---|---|---|
| **信息量** | 被用字数 | 大块 | 答案引用了多少实质内容 |
| **能否答出** | 空洞率 | 大块 | 证据够不够拼出答案 |
| **精炼度** | 利用率 | 小块 | 念的内容里有多少没用 |
| **忠实度** | 溯源率 | 无关 | 有没有超出证据编造 |
| **代价** | 答案字数 / 延迟 | 小块 | 用户等多久、读多少 |

★ 前三类构成真正的权衡，第四类是不能退化的底线，
代价侧决定这个权衡值不值得。

### 10.4 权重敏感性分析（结论稳健性检验）

不同权重方案下的最优块长：

| 权重方案 | 最优块长 |
|---|---|
| 均衡 1/3 | 2048 |
| 重信息量 | 2048 |
| 重能答出 | 2048 |
| 只用被用字数 | 2048 |
| 只用空洞率 | 2048 |
| **重精炼** | **384** ← 唯一反向 |

**6 种方案里 5 种指向 2048**，唯一反向的恰好是第一版误用的那个指标。

★ 这个分析的价值：**结论不依赖我选的那个权重。**
   若所有方案都指向同一值 → 结论稳健；
   若随权重变化 → 只能展示权衡结构，不该给唯一推荐。

### 10.5 ★★ 这条规律是通用的

> **任何单一指标都必然偏向某个方向。**
> 判断一个指标是否可用，要看它的「最优解是否随权重/口径翻转」——
> 翻转说明它只测了一个维度。

**可迁移到本项目的其他决策：**

| 决策 | 指标偏向 | 该同时看 |
|---|---|---|
| 块大小 | 大/小（本文） | 信息量 + 精炼度 + 代价 |
| 检索重排 | 召回/精度 | gold 定义 + 首位命中 + 延迟 |
| 冲突消解策略 | 置信度/保守性 | 敏感性分析 + 可用比例 |

M3 之所以得出错误结论，不是「指标算错了」，
而是**用了一个必然偏向的指标，且没检查它的偏向性**。

## 十一、★ M11：把生成层接进服务，暴露了「跨语言忠实度」问题

M6 的忠实度评测是**离线**做的，答案是照抄英文原文。
M11 把生成层接进 API 后，答案变成**中文** —— 立刻暴露一个全新问题。

### 11.1 现象

同一个问题（描述类），忠实度只有 0.75，而 M6 离线测是 0.91。

### 11.2 定位：逐句打印中间量

不能停在数字层面，必须看**每句为什么被判无据**：

```
证据原文（英文）：with a human body and a dark canid's head
答案（中文）    ：具有人类的身体和黑暗犬类的头
```

**这是逐字翻译，完全忠于证据。** 但中文词对不上英文 token → 判为无据。

### 11.3 ★★ 修的过程：7 轮，每轮都冒出新问题

| 轮 | 改法 | 新问题 |
|---|---|---|
| 1 | 加中英等价映射表 | 双字切分 vs 整词，粒度对不上，永远匹配不到 |
| 2 | 改短语级匹配 | 「钢铁+激光」这种**纯幻觉被判成有据**（ratio 1.00） |
| 3 | 让 `_content_tokens` 切中文 | 发现原实现**根本不切中文** → 中文部分「免费通过」 |
| 4 | 只保留映射表内的双字窗口 | 滑窗产生大量跨词边界垃圾 token（`体和`/`和黑`），ratio 被压到 0.21 |
| 5 | 加「未映射概念守卫」 | 守卫用 `concept not in ev_set`，但 ev_set 是英文 → 真实翻译被误杀 |
| 6 | 守卫容许所有格变形 | `canid's` vs `canid` 对不上 |
| 7 | 守卫改「全部词命中」 | 「猫头」→ cat head，`head` 命中就放行 → **漏判幻觉** |

★ **第 7 轮是最严重的问题**：漏判幻觉意味着**指标直接失效**，
比误判更糟。

### 11.4 最终方案：守卫 + 豁免 + 映射表收紧

```python
# 1) 跨语言映射（只收「可替换的具体名词」，≥2 字）
"犬类的头": "canid head", "翅膀": "wing", "头饰": "headdress", ...

# 2) 守卫：映射表里有、而证据里查不到 → 判定为幻觉
#    多词短语必须**全部**命中（ALL，不是 ANY）
if _has_unbacked_concept(sentence, ev_set):
    return False, 0.0

# 3) 豁免：句子在**正确声明「证据里没有」**
if is_hedge_sentence(sentence):
    return True, 1.0
```

### 11.5 ★★ 映射表收录标准（踩坑总结）

| 类别 | 例子 | 判定 |
|---|---|---|
| **可替换的具体名词** | 犬头 / 翅膀 / 头饰 / 钢铁 | ✓ 收 |
| 单字泛用词 | 外 / 力 / 速 | ✗ 「外观/外形」全中 → 误杀 |
| 泛用描述词 | 形象 / 特点 / 特征 | ✗ 同上 |
| 泛用动词 | 出现 / 描绘 / 组成 | ✗ 同上 |
| **维度名** | 破坏力 / 速度 | ✗ 证据写 "Destructive Power"，映射成 destruction 对不上 → **误杀正确答案** |

★ 维度正确性交给 `numeric_faithfulness` 判（它用维度别名表），不混进溯源。

### 11.6 ★★ 另一个独立缺陷：正确拒答被判幻觉

实测：「Made in Heaven 的外观形态方面没有具体描述」→ 忠实度 **0.000**

但这是**正确答案**（该替身确实没有外观描述）！
问题在于：这类句子断言的是「证据里没有」，天然不含证据里的词
→ 词级覆盖率必然很低 → 被误判。

→ 加 `is_hedge_sentence()` 豁免：**正确声明「证据里没有」是忠于证据的最高形式**。

### 11.7 ★ 一个我走错了的方向

中途尝试「直接剥掉开场套话」（`根据提供的证据，描述如下：`），
结果**幻觉被放过**：

```
「Tusk 的外观是蓝色的」→ 剥掉套话后无 token → 判 True
```

★ **教训**：改动判定逻辑时，「让某些输入被判True」极度危险 ——
分母变空、映射失效、阈值失效，任何一个都会变成「什么都能判对」
（这正是 M3 踩过的「乱码证据也能拿满分」）。

**最终改法**：不剥句子，只把套话 token 从 ratio 的**分母**里排除，
保留短语判定 —— 幻觉仍会被抓。

### 11.8 结果

| 问题 | 修复前 | 修复后 |
|---|---|---|
| Anubis 外观形态 | 0.750 | **1.000** |
| Tusk 形态外观 | 1.000 | **1.000** |
| Made in Heaven 外观 | **0.000** | **1.000** |

回归：维度隔离 9/9、跨语言 9/9、M6 原用例全部正常、敏感度检验有效。

### 11.9 ★★ 仍未解决的根本问题

> **词级覆盖率对中文天然失灵。**
> 中文句子里的实体名（Anubis、Tusk）能命中英文 token，
> 但中文描述部分（「蓝色的」「钢铁的」）不在词表里——
> 除非把它们全加进映射表，否则 ratio 永远只数得着几个英文名。

当前用「映射表 + 守卫」把已知部件管住，但**未知的中文描述仍可能漏判**。

真正的解法是**语义层面的忠实度判定**（如 NLI 交叉编码器），
但那会引入模型依赖，与 M6 「不用 LLM 判分」的立场冲突。

★ **这是一个明确的未解决取舍，不是遗漏。**
