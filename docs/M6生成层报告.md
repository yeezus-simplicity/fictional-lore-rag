# M6 生成层与忠实度评测报告

> 完成日期：2026-10-06
> 范围：接入 Qwen2.5-1.5B 生成层 + 忠实度四配置对照评测
> **核心结论：RAG 有效性得到 88.1pp 的强证据支持；指标实现经历 11 轮修错，过程比结果更有价值**

---

## 1. 为什么先做指标设计

M3 的教训：**两次「指标与目标脱钩」都让实验结论作废**。

M6 要回答的是「答案是否忠实于证据」。如果不先把「怎么算忠实度」定清楚，
跑出来的数字没有任何意义。所以顺序是：

```
指标设计（faithfulness_design.md）→ 指标实现 → 真实数据验证 → 修复 → 再跑
```

## 2. ★ 关键决策：不用 LLM-as-judge

| 方案 | 可靠性 | 否决理由 |
|---|---|---|
| **机械核对（采用）** | 高 | 纯字符串/正则/集合运算，可复现 |
| LLM-as-judge | 低 | 1.5B 做评审员本身不可靠；换强模型又引入「评审模型的评测」问题 |

**小模型也能被可靠评测**——因为「是否忠实」是二元、可机械核对的，
比「是否聪明」简单得多。1.5B 测不好只能说明**证据组织得不好**，这本身就是要测的信号。

## 3. ★★ 核心结果：RAG 有效性

### 3.1 四配置对照（30 题，Qwen2.5-1.5B，temperature=0.1 采样）

> ⚠️ **M9 复核时发现此处标注有误**：0.1 仍是随机采样（`do_sample = temperature > 0`），
> 本节数据作为**单次观测**有效，但不能声称「可复现」。
> 详见 [M9 索引验证报告 §3](M9索引验证报告.md)。

| 配置 | 溯源 | 数值 | 实体 | 矛盾率 | 利用率 | 空洞率 |
|---|---|---|---|---|---|---|
| **A 生成式 + 真实证据** | **0.9138** | **1.0000** | 1.0000 | 0.0000 | 0.1855 | 0.3667 |
| B 抽取式（M5 现状） | 1.0000 | n/a | 1.0000 | 0.0000 | 0.4367 | 0.0000 |
| C 生成式 + 空证据 | 0.0333 | n/a | 0.0000 | 0.0000 | 0.0000 | 0.7333 |
| D 生成式 + 无关证据 | 0.1083 | n/a | 0.1333 | 0.0000 | 0.0390 | 0.7000 |

### 3.2 三个判读

**① 证据有效性（最关键）**

```
A（有证据）  0.9138
C（无证据）  0.0333     → 差 88.1pp
```

同一个模型、同一批问题，**唯一变量是「给不给证据」，结果差 88 个百分点**。

这直接回答了项目最核心的假设：**RAG 不是装饰层，证据确实在约束输出。**

**② 指标敏感度（指标本身有效吗）**

```
A（相关证据）  0.9138
D（无关证据）  0.1083    → 差 80.6pp
```

指标能区分证据质量。**若 D 组也接近 A 组，说明指标测不出差异，是无效指标。**

**③ 生成 vs 抽取的代价**

```
抽取式（B）  1.0000  ← 照抄不可能幻觉
生成式（A）  0.9138
→ 生成带来 8.6pp 的忠实度损失
```

**这个 8.6pp 是「自然语言表述」的定价。** 换来的好处是可读性——
抽取式返回原文片段，生成式返回能直接读的答案。

### 3.3 ★ 一个意外发现：模型「不敢答」

| 配置 | 空洞率 |
|---|---|
| A（有证据） | 36.7% |
| C（无证据） | 73.3% |
| D（无关证据） | 70.0% |

A 组的空洞样例：
```
Q: Foo Fighters 的持续力是几级？
A: 提供的证据中未提及 Foo Fighters 的持续力等级。
```

**36.7% 的问题里，模型因为「证据里没有」而拒答。**

这不是缺陷，是**忠实度约束在起作用**——查证后发现这些替身的对应维度
数据本身就是 `?`（UNKNOWN），模型照实说了。

C 组样例更直接：
```
Q: Echoes (ACT3) 的速度等级？
A: 提供的证据中未提及 Echoes (ACT3) 的速度等级。  ← 完全正确
```

**结论：1.5B 模型在 system prompt 约束下「宁可说不给，也不编」。**
这与「小模型容易幻觉」的直觉相反——**前提是有明确的忠实度约束**。

### 3.4 延迟代价

| 配置 | 总耗时 | 平均延迟 | 平均 token |
|---|---|---|---|
| A 生成式 | 220s / 30 题 | **7277 ms** | 61 |
| B 抽取式 | 1s / 30 题 | 0 ms | 0 |
| C 空证据 | 61s | 1974 ms | 19 |
| D 无关证据 | 102s | 3334 ms | 30 |

**生成式比抽取式慢约 7 秒/题**（61 token）。这是可读性的定价。

★ 值得注意：**证据越多，生成越慢**（C 组 19 token vs A 组 61 token）——
说明模型在无证据时会直接说「未提及」而不展开。

## 4. ★★★ 指标实现：11 轮修错（比结果更有价值）

指标设计得再好，实现出来照样全是坑。以下每一轮都是**被真实数据打脸**才发现的。

| 轮 | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | `"a"` 在 `"rated"` 里匹配上 | 子串匹配 | 切词建集合再判断 |
| 2 ★★ | 乱码证据下溯源仍 1.00 | **词袋模型下打乱顺序不改变 token 集合** | 加 2-gram 连续短语 |
| 3 | `破坏力不是A级` → 维度=「破坏力不」 | 否定词被吞进维度名 | 先按否定切分 |
| 4 ★ | numeric 全为 0 | T4 没有数值断言 | 混采 T1/T7；显示区分 None 与 0 |
| 5 ★ | `射程是 5 米` 全判错 | 证据是**带单位物理量** | 分「等级」「物理量」两条路径 |
| 6 ★★ | `300米` 截成 `3` | `\d(?:\.\d)?` 只匹配 1–2 位 | 改 `\d+` |
| 7 ★★★ | `A=5` 算成 `E` | 自己写 `abcde[4-n]`，n=5 时索引 **-1 绕回** | 复用 `encode.py` 权威映射 |
| 8 ★★ | `速度是 A` 判对 | ±20 词窗口把**相邻维度**的值圈进来 | 最小窗口 + 遇下个维度即停 |
| 9 ★ | 维度抽成「力等级定」 | 正则 `[一-鿿]{2,4}?` 切碎 | 放弃捕获组，改「就近回溯」 |
| 10 ★ | 序列号「1.」被当断言 | 列表序号污染 | `_is_list_index()` 过滤 |
| 11 ★ | `Diavolo` 的 D 当成等级 | 等级字母未要求独立出现 | 加 `(?<![A-Za-z])` 词边界 |

### ★★ 贯穿全部 11 轮的一个模式

**所有 bug 都表现为「指标太宽松，什么都能判对」，没有一个表现为「报错」或「明显异常」。**

- 轮 2：乱码证据也能拿满分 → **看起来还很漂亮**
- 轮 7：`A=5` 算成 `E` → 数值「有值」，看不出错
- 轮 8：速度借用破坏力的值 → 判为「正确」
- 轮 10：序号当断言 → 只是**略微**拉低分数

**若只跑一遍看总分，11 个 bug 里有 8 个根本发现不了。**

→ **必须逐条打印中间量**（`details`、`candidates`、维度映射），
让每个判定都能被单独检验。

### 数值指标的修正轨迹（最能说明问题）

```
0.0000  ← T4 没有数值断言（题型选择错）
0.0000  ← 物理量当等级比对
0.2222  ← 序列号污染
1.0000  ← 全部修好
```

**同一份数据、同一个模型，指标从 0 到 1。** 如果只跑最终版本，
会误以为「模型表现完美」；如果只看第一版，会误以为「模型全错」。

### 三条可迁移规则

| 规则 | 出处 |
|---|---|
| **映射表必须复用数据层定义** | 轮 7：`encode.py` 里已有 `GRADE_TO_VALUE`，不该自己推导 |
| **判定要「独立出现」而非子串包含** | 轮 1、11：`a`∈`rated`、`D`∈`Diavolo` 是同一类错误 |
| **邻近窗口必须有边界** | 轮 8：「维度词后 N 个词」的 N 要有停止条件，否则串到邻居 |

## 5. ★ 自检：这套指标本身可信吗

按 M3 的 4 问自检：

| 自检项 | 回答 |
|---|---|
| gold 粒度与配置匹配吗 | ✓ 忠实度的 gold 是「证据块」，与检索配置无关 |
| 多配置量纲一致吗 | ✓ 四组用同一套指标，只变证据处理 |
| 「改进」需要改系统代码吗 | ✓ 指标只读答案与证据 |
| **负向结果违反常识吗** | ✓ C 组 3.3%、D 组 10.8% 都很低，符合「无证据则无法溯源」 |

**额外做的两项检验**：
- **敏感度检验**（D 组）：指标能区分证据质量（差 80.6pp）✓
- **空证据检验**（C 组）：模型 96.7% 时说「未提及」，符合预期 ✓

## 7. ★ 意外收获：A 组利用率只有 18.6%

抽取式（B）的利用率是 **0.4367**，生成式（A）只有 **0.1855**。

这说明**检索到的块里，超过 80% 的内容没被答案用到**。

**这直接指向 M3 遗留的「块大小」问题** —— M3 发现 chunk_size 越大指标越好
（2048 时全 1.0），当时判断是「指标退化」；现在有了生成层，
**可以用「利用率」这个真实指标来重新评估块大小**。

★ 这是 M3 遗留问题的**解决路径**，而不是又一个待办：
指标退化导致无法判断块大小是否真的重要，现在可以用生成层测利用率。
