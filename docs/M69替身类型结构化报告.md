# M69 报告：替身类型结构化 —— 从「一坨粘串」到可查询的三段

> 完成日期：2026-10-16
> 承接：M67 报告 §8 明确记下的遗留项
> 规模：188 个替身 / 169 条非空类型值 / **残余 0**

---

## 0. 一句话

`stands.stand_type` 一直是 Infobox 多项**直接拼接**的粘串。
M32 在展示层洗过一次，但词表只有 15 词、且漏掉了关键的子串歧义；
本轮把切分下沉到数据层，**一次跑通、残余为 0**，并让展示层与写库层共用同一份词表。

---

## 1. 问题原貌

```
Close-RangeRange IrrelevantNatural HumanoidSentientEvolved
AutomaticMaterializedPsychological AssaultArtificial Non-HumanoidMulti-UserSentient
Long-RangeNatural Non-HumanoidMaterialized
```

没有分隔符、没有括注边界，直接显示没法看，也**没法按类型检索**。

### M32 的展示层清洗为什么不够

| 问题 | 实测后果 |
|---|---|
| 词表只有 15 词 | `Natural Non-Humanoid` / `Psychological Assault` / `Sentient` / `Multi-Unit` / `Multi-User` / `Foresight` / `Evolved` **全部不识别** |
| `Natural Humanoid` 是 `Natural Non-Humanoid` 的**子串** | 先命中短的 → 「自然非人型」被显示成「自然人型」 |
| 只在输出时算 | 底层值仍是粘的 → 任何过滤/统计都得在 SQL 外自己再解析 |
| 词表定义在 `api/main.py` | 数据侧无法复用，两边各切各的 |

## 2. ★ 为什么现在能做（M67 当初放弃了这件事）

M67 修 owner 粘连时**明确拒绝**碰 `stand_type`，理由写在代码注释里：

> `{{ST}}` 是缩写模板，无法从 wikitext 可靠**展开**。

本轮**不做展开** —— 只切分 `stands.json` 里**已经展开好**的值。
词表由实测反推（`dataset/pipeline/diagnose_stand_type.py` 先跑一遍，
把「残余」打印出来，逐个补进词表），最终 **168 个非空值残余为 0**。

> **残余为 0** 是本轮唯一的硬判据：
> 它意味着每个字符都能被某个已知词解释，没有猜测成分。
> 如果残留了 `Evolved` 这种没见过的词，那就是词表不全，
> 应该如实留在 `stand_type_residual` 里等补词，而不是猜一个。

### 词表反推的过程

```
第 1 轮（起始 15 词 + 语料实测补 5 词）：156 可分解 / 12 有残余
  残余只有两种：foresight（5 条）、evolved（7 条）
第 2 轮（补 Foresight / Evolved）：168 可分解 / 0 有残余
```

## 3. 设计

### 3.1 切成三段而不是一段列表

| 段 | 列 | 含义 |
|---|---|---|
| 射程 | `stand_type_range`（主）/ `stand_type_ranges`（全部） | Close-Range / Long-Range / Range Irrelevant / Long Distance |
| 体质 | `stand_type_kinds` | Natural/Artificial × Humanoid/Non-Humanoid |
| 特性 | `stand_type_extras` | Automatic / Materialized / Sentient / Multi-User … |
| 审计 | `stand_type_residual` | 未识别残余（期望恒为 `''`） |
| 审计 | `stand_type_aggregate` | 是 load_db 合成的形态组父子标记 |
| 展示 | `stand_type_cn` | 中文可读串，与切分严格同源 |

原 `stand_type` 列**保留不删** —— 它是 Infobox 原文，可回溯；
新列是派生值，可重算。

### 3.2 ★ 源站本身就矛盾，如实记录而不是替它做主

写测试时我断言「不可能同时命中人型和非人型」，DB 跑出来两条真命中：

| 替身 | 原始串 |
|---|---|
| Aqua Necklace | `Long-RangeMaterializedNatural HumanoidNatural Non-Humanoid (Water)` |
| Notorious B.I.G | `AutomaticNatural Non-Humanoid (Post-Mortem)Natural Humanoid (Original)` |

查证后确认：**这是源站真实数据**（B.I.G 原体人型、死后非人型），
不是我的切分错误。→ 数组列如实记录，`range_type` 只作为「主射程」供展示。

> 这条比代码 bug 更值得记：
> 我第一反应是「我的代码错了」，但**先查原始串**才没把对的改成错的。
> 一旦为了让断言通过而改成单值，就等于替源站编数据了。

同样地，`Range Irrelevant` 我最初归进了「特性段」，
导致 `all_en()` 的顺序与源串不符 —— 也改成了归入射程段并保序。

## 4. 落地过程中踩的坑

### 4.1 ★ psycopg2 的数组字面量在 VALUES 里根本不能用

```
psycopg2.errors.SyntaxError: syntax error at or near "{"
LINE: NULL,{"Artificial Non-Humanoid"},{"Autom...
```

实测三种写法**全都失败**：

| 写法 | 结果 |
|---|---|
| 传 list（走 psycopg2 的 AsIs adapter → `{"a","b"}`） | ✗ `syntax error at or near "{"` |
| `{"a","b"}::text[]` | ✗ 同上 |
| `ARRAY['a','b']::text[]` 走占位符 | ✗ 同上 |
| `ARRAY['a','b']::text[]` 内联进 SQL 字符串 | ✓ OK |

**根因**：裸数组字面量 `{...}` 的类型要靠上下文推断，
在 `VALUES` 列表这个位置推不出来；而 `ARRAY[...]` 走构造函数语法不依赖推断，
但**一走占位符就会被整体加引号**。

**解法**：数组列传「竖线分隔的字符串」，SQL 侧
`coalesce(string_to_array(%s,'|'),'{}'::text[])` 还原。
`coalesce` 是必须的 —— `string_to_array(NULL)` 返回 NULL，会撞 NOT NULL 约束。
用 `|` 而非 `,`：`stand_type` 串里出现过逗号，词表里没有竖线。

### 4.2 ★ 硬编码列下标，静默算错

```python
_n_res = sum(1 for r in stand_rows if len(r) > 17 and r[17])   # ❌ 下标错了
```

加了一列之后没同步 → 报出「未识别残余 **106** 条」。
106 这个数字**看着像真问题**（像是词表大面积失效），
实际是下标指向了 `extras` 那一列。

改法不是把 17 改成 18，而是用 tuple unpack：

```python
(_sid, _en, ..., _rng, _rngs, _kinds, _extras, _res, _agg, _cn) = _r
if _res: _n_res += 1
```

字段数不对会**立刻** `ValueError`，而不是静默算出一个像真的数字。

> ★ 这是老教训的第三次变体：**报错看起来像数据问题，
> 其实是索引/引用写错了**。先怀疑判据，再怀疑数据。

### 4.3 NamedTuple 不能有下划线开头的字段

改结构时想把「命中区间」放进结果对象，用 `_words` / `_hit_idx` 命名 →
`ValueError: Field names cannot start with an underscore`。
改用 `@dataclass(frozen=True)` + 公开字段名。

### 4.4 PG 的 `->>` 是 JSON 运算符，不是数组取值

测试里写了 `stand_type_ranges ->> 1` → `UndefinedFunction: text[] ->> integer`。
数组取值要用 `stand_type_ranges[1]`。

## 5. 效果

| 项 | 前 | 后 |
|---|---|---|
| 底层类型值可查询 | ✗ 粘串 | ✓ 三段结构化 + 索引 |
| 词表覆盖 | 15 词 | 25 词（实测反推） |
| 「近距离型 + 自然人型」检索 | 做不到 | ✓ 一条 SQL |
| 展示层与数据层词表 | 两份，可能不一致 | ✓ 同一份模块 |
| 子串歧义（人型/非人型） | 会切错 | ✓ 长词优先 + 测试锁死 |
| 未识别残余 | 不可见 | ✓ 168/168 为 0，且有闸门 |

实测能回答的问题（以前一个都答不了）：
- 「近距离型 + 自然人型的替身有哪些」→ `stand_type_range = 'Close-Range' AND 'Natural Humanoid' = ANY(stand_type_kinds)`
- 「有自主意识（Sentient）的替身」→ `'Sentient' = ANY(stand_type_extras)`
- 「哪些替身源站给了矛盾射程」→ `cardinality(stand_type_ranges) > 1`

## 6. 遗留

- 词表仍是**英文**词 + 静态中文映射。若后续要接社区标准译名，
  应替换 `_CN` 而不是加第二份映射。
- `stand_type_cn` 由中文词表拼成，与「官方中文译名」无关，
  展示时不应被当作权威译名引用。
- 形态组父子记录（`Aggregate (form group)`）已单独标记，
  但形态组本身仍未消解（M45 的遗留，与本轮无关）。
