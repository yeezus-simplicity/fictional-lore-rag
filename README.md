# rag-kb · 企业级 RAG 知识库平台

> 面向企业文档的全链路检索增强生成（RAG）系统。
> 覆盖文档解析 → 语义切块 → 混合检索 → 重排 → 流式生成 → 量化评测 → 服务化监控。

**状态：🚧 立项阶段（v0.1）** — 架构设计已完成，尚未开始编码。

---

## 项目定位

市面上大量 RAG 项目停留在「基于 LangChain 的聊天机器人」层面。本项目追求的是**可量化、可压测、可上线的系统级工程**，三个核心差异点：

| 差异点 | 说明 |
| --- | --- |
| **量化评测体系** | 自建200 条标注评测集，Recall@K / MRR / nDCG / 忠实度全指标，每次迭代自动出对比表。所有优化都有数据支撑，不靠主观判断。 |
| **C++ 服务层** | SSE 流式输出、epoll 事件循环、线程池与并发控制、语义缓存、多租户隔离。工程性能是可讨论、可深挖的。 |
| **成本与延迟工程** | TTFT / TPOT / P99 延迟分解、按 token 计成本模型、缓存命中率。回答「这个系统一年要花多少钱、快到什么程度」。 |

## 架构概览

```
文档接入 → 解析为 Document AST → 标题层级语义切块
                ↓
        向量索引(ANN)  +  倒排索引(BM25)
                ↓
     Query 改写 → 并行召回 → RRF 融合 → 交叉编码器 Rerank
                ↓
  上下文组装 → 流式生成 → 引用溯源 → 低置信度拒答
                ↓
   C++ 服务层(SSE/并发/缓存/多租户) + Prometheus 监控
```

详细架构与设计决策见 [`docs/立项书.md`](docs/立项书.md)。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 解析 | PyMuPDF · unstructured · trafilatura |
| 切块 | 自实现可插拔策略（支持 A/B 对比实验） |
| Embedding | bge-m3 / Qwen3-Embedding |
| 向量库 | Milvus（主）· pgvector（备选） |
| 稀疏检索 | BM25（Elasticsearch / Milvus） |
| 重排 | bge-reranker-v2-m3 |
| 生成 | Qwen2.5-7B-Instruct（本地）· API 双通道 |
| 服务层 | **C++20**（epoll · 线程池 · SSE）|
| 编排 | LangGraph 或自实现轻量状态机 |
| 监控 | Prometheus + Grafana |
| 评测 | 自建评测集 + RAGAS 交叉验证 |

## 核心设计决策

项目中每一项优化都是一个**可验证的实验假设**，而非既定结论：

- **D1** 切块策略：固定长度 / 递归字符 / 标题感知 / 语义分块
- **D2** 检索模式：纯向量 / BM25 / 混合 RRF 融合
- **D3** Rerank 策略与候选深度
- **D4** 混合权重 α 扫描
- **D5** 语义缓存阈值与误命中权衡
- **D6** 生成模型规模的成本-准确率权衡
- **D7** Chunk 尺寸与重叠参数扫描

每项决策最终产出一张对比表，这是项目技术文档的核心，也是面试时最有力的谈资。
