# 评测设计的两次「指标与目标脱钩」

> 记录：2026-10-03 · M3 实验过程中连续踩到的两个坑
> **这不是实验报告，是方法论复盘** —— 两个坑的代价是得出完全相反的错误结论

---

## 为什么要单独写

M3 跑了 25 组实验，但最有价值的产出不是那些数字，而是**两次差点得出错误结论的排查过程**。

两次都是同一类错误：**指标可以无成本地被"优化"，而实际系统并没有变好。**

---

## 第一次：D1 溯源映射（结论被颠倒）

### 现象

```
第一版判分：fixed 0.5134  >>  semantic 0.1739    ← 结论：固定长度好 3 倍
```

按这个结论，语义切块毫无价值，M1 的切块设计是错的。

### 根因

评测集的 gold `chunk_id` 是按**语义切块**生成的。换固定长度切块后 gold 失效，
我做了溯源映射：把 gold 语义块映射到「包含它的 view 集合」，
**命中任一即算召回**。

问题在于：固定长度切块下，1 个语义块平均对应 **1.96 个 view**。

```
语义切块：1 个语义块 = 1 个 view     → 命中即精确命中
固定切块：1 个语义块 ≈ 1.96 个 view  → 命中任一就算，判分标准被放宽
```

**等于给固定切块开后门。**

### 修正

改用**字符级溯源覆盖率**，两种切块粒度量纲一致：

```
coverage(g) = |命中 view 中属于 g 的字符数| / |g 的总字符数|
```

| 切块策略 | 溯源覆盖率 | 完整覆盖率 |
|---|---|---|
| semantic | 0.8605 | 0.8261 |
| fixed | 0.9352 | 0.8913 |

差距从 **3 倍缩到 8%**。

### 教训

> **换实验配置时，要检查"gold 的粒度"是否随之变化。**
> 如果 gold 与实验对象的粒度耦合，判分标准就会悄悄漂移。

## 第二次：D3 重排（负向 17%）

### 现象

```
无重排基线：recall@5 = 0.6250, nDCG@5 = 0.4049
重排 Top-20：recall@5 = 0.5181, nDCG@5 = 0.3261      ← 全面恶化
```

Rerank 交叉编码器通常是质量提升最狠的手段（业界共识），这里却是负向。
**按数据走就等于得出「重排有害」的荒谬结论。**

### 三层排查

**排查一：召回池不足？**

第一版实现里，融合后只产出 20 条，而重排池设为 50 —— 候选被截断。

修复：`召回深度 = max(2k, rerank_candidates, 20)`。
**结果没变**，排除。

**排查二：实现有 bug？**

手工构造 4 个候选，验证 reranker 判别力：

```
QUERY: Yellow Temperance的PHYSICAL IMPERVIOUSNESS方面有哪些描述？
  正确块           score = +0.9183
  含关键词的干扰块    score = +0.1442
  同替身其他块       score = +0.3050
  其他替身         score = +0.0001
```

**判别力极强，实现无误。**

**排查三：gold 定义与检索目标不匹配（真因）**

看「gold 首位次分布」：

| 指标 | 基线 | 重排 |
|---|---|---|
| gold 首位次（平均） | 5.29 | 6.51 |
| gold 在 Top-3 | 0.5111 | 0.3556 |
| **recall@20** | **0.9547** | **0.9547** |

**recall@20 完全不变** —— 重排没丢任何召回，只是换了顺序。

那它换的顺序对不对？换一个更合理的 gold 定义再看：

| gold 定义 | 平均 gold 块数 | 基线 | 重排 | 变化 |
|---|---|---|---|---|
| **单块**（生成问句时用的那个） | 1.2 | 0.6250 | 0.5181 | **−17.1%** |
| **同替身全部块** | 19.2 | 0.3043 | 0.3015 | −0.9% |

**换 gold 定义后，重排从"恶化 17%"变成"基本持平"。**

### 根因

T4/T5 的 gold 是「**生成问句时所用的那个块**」，
而好的检索应该返回「**该替身的所有相关块**」。

重排把同替身的其他相关块提到了前面 —— **这正是重排在正确工作**。
但评测只认那一个特定块，于是被判为"恶化"。

### 修正（排期至 M8）

- gold 从「特定块」改为「相关块集合」（`(stand_id, section)` 相同即相关）
- 主指标从 recall@K 改为 **首位命中率 / MRR**（更贴近「用户看到的第一条是否正确」）
- 引入生成侧判据：「答案是否被正确引用」

|---|---|---|
| 表面现象 | fixed 好 3 倍 | 重排恶化 17% |
| 实际| 判分标准被放宽 | 判分标准过严 |

| 修正手段 | 统一量纲（字符级覆盖率） | 放宽 gold（相关块集合） |
| 若未发现 | 砍掉语义切块设计 | 得出「重排有害」并放弃 Rerank |

## 核心教训

### 1. 指标可以被无成本优化，而系统并未变好

两次都是：只需改动某个「判分方式」或「实验对象粒度」，分数就会大幅变化，
而**实际系统的行为完全没变**。

**判据**：如果一个「改进」不需要改任何系统代码就能让指标提升，
那它提升的是指标，不是系统。

### 2. 换实验配置时必须检查 gold 是否还成立

D2 换检索方式、gold 不变 → 有效。
D1 换切块粒度、gold 失效 → 我做了映射但映射方式有偏。
D3 换排序方式、gold 语义不匹配 → 完全没意识到。

**同一套评测集，在不同实验下 gold 的含义可能不同。**

### 3. 负向结果值得深挖，不要直接接受

D3 的负向结果违反业界共识，这本身就是信号——
**要么我的实现错了，要么我的测量错了**。

三层排查（召回池 → 打分合理性 → gold 定义）花了约 40 分钟，
但避免了「砍掉重排模块」这个错误决策。

### 4. 数字会骗人，量纲不会

D1 里 `0.5134` 与 `0.1739` 相差 3 倍，但两者**量纲不同**（一个是 view 命中率，
一个是语义块命中率），根本不可比。

**统一量纲后差距只有 8%。**

## 改进清单（已排期）

| 优先级 | 事项 | 目的 |
|---|---|---|
| 高 | gold 增加「相关块集合」概念 | 修正 D3 的测量问题 |
| 高 | 主指标改为首位命中率 / MRR | 更贴近用户感知 |
| 中 | 评测集增加「多块答案」题型 | 当前 T4/T5 gold 天然是单块 |
| 中 | 报告加入「指标有效性自检」章节 | 每次实验前先确认 gold 与配置匹配 |
| 低 | 引入「精确率/ 无冗余度」指标 | 惩罚过大的块（D1b 指标退化） |
