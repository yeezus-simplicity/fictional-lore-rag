## 4. ★ 规范需要修订：条件值的两种形态

原规范 v1.0 把条件值统一处理为"按状态拆多行"，但实测发现条件值有**两种截然不同的语法形态**，处理方式完全不同。

### 形态一：`X※<描述>` —— 有基础等级（20 个格子）

```
B※20-30 meters
C※Range: 2 m (6.6 ft)
A※Only during replays
E※Restraining Power: A
```

特征：首字符是 `A`–`E`，`※` 之后是**补充说明**。基础等级可直接提取，说明部分存入 `condition_note`。

**处理**：`stat_value` = 基础等级数值；`condition_note` = `※` 后的文本。
例：Baby Face 的 `A※` → `stat_value=5, condition_note="Restraining Power: A"`

### 形态二：`※<描述>` —— 无基础等级（4 个格子）

```
※Complete
※Depending on Education
?※Power: Likely A (JoJoveller p.245)
D※Speed: Refers to "Melt your Heart" Ability (JoJoveller p.245)
```

特征：`※` 出现在**首位**，前面没有等级，或只有一个 `?`/`D` 等非标准前缀。

**处理**：**不可数值化**，`stat_value=NULL`，`category=CONDITIONAL`。
例：Gold Experience 的 `※Complete`（DEV 维）→ `NULL + CONDITIONAL`

### 修订后的判定规则

```
if value matches ^[A-E]※    -> category=RANKED, stat_value=map(A..E),
                              condition_note=value[2:]
elif value matches ^[?∅∞]※ -> category=CONDITIONAL_NO_BASE, stat_value=NULL,
                              condition_note=value[2:]   # ?※ 形态
elif value starts with ※    -> category=CONDITIONAL_NO_BASE, stat_value=NULL,
                              condition_note=value[1:]
else                         -> 常规五类映射
```

> 规范 v1.0 的「按状态拆多行」方案仅适用于**跨状态数值不同**的情况（如 Black Sabbath 觉醒前后不同）。而本数据集中的 `※` 绝大多数是「同一数值 + 补充说明」，不涉及多行展开。**已修订。**

## 5. ★★ 严重陷阱：CSV 列名 `PER` vs `STA`

两份 CSV 镜像的第 4 列命名不一致：

```csv
# topologytomato/j2.csv
Stand,PWR,SPD,RNG,PER,PRC,DEV      ← PER

# BogdanG888G/j3.csv
Stand,PWR,SPD,RNG,STA,PRC,DEV,Story  ← STA + 额外的 Story 列
```

**`PER` 在不同数据集里含义不统一**：
- 在某些替身数据集中指**持续力**（Persistence）
- 在另一些语境下指**感知力**（Perception）

若按列名自动映射，会把「持续力」错映射为「感知力」，**且不会报错，只会静默产出错误统计**。

**处理决策**：
- 统一以jojowiki 的 `STA`（Stamina/持续力）为权威列名
- CSV 源的 `PER` **不按名映射，按位置映射**（第4 列 = STA）
- 校验规则新增 **V9：列名白名单校验**，防止未来接入新源时按名误映射

## 6. ★ 交叉校验结果：两份 CSV 有 34 处实质冲突

以 jojowiki 为主源基准，对两份 CSV 做位置对齐比对：

```
匹配 155 条：一致 121，不一致 34
```

### 冲突类型 A：空值表示法不同（占多数，非真冲突）

| 替身 | j2 | j3 |
| --- | --- | --- |
| Achtung Baby | `None` | `undefined` |
| Atom Heart Father | `None` | `undefined` |
| Super Fly | `None` | `none` |
| Stray Cat | `None` | `undefined` |
| Star Platinum | `A` | `undefined`（DEV 维） |

**这揭示了一个规范缺口**：原规范只定义了 `∅` 作为空值标记，但**不同数据源用不同字面量表示同一个语义**。需扩展空值字面量白名单。

| 字面量 | 来源 | 归一类别 |
| --- | --- | --- |
| `∅` | jojowiki | `EMPTY_SLOT` |
| `None` / `none` | CSV 镜像 | `EMPTY_SLOT` |
| `undefined` / `N/A` | CSV 镜像 | `EMPTY_SLOT` |

> **注意**：`?` 不在此白名单内。`?` 是「未知」而非「空位」，必须保持独立（见数据规范 §1.4）。

### 冲突类型 B：数值实质不同（真冲突，需记录消解）

| 替身 | 维度 | j2 | j3 | 备注 |
| --- | --- | --- | --- | --- |
| **Echoes (ACT3)** | 全部 6 维 | B B C B C A | A C D C C B | **完全不同记录**，疑似 j3 把 ACT1/ACT2 数据错配 |
| **Black Sabbath** | PWR | `A` | `E` | 与 jojowiki 的 `E※` 一致（E 为基础等级） |
| Star Platinum | DEV | `A` | `undefined` | j3 缺失 |

**Echoes (ACT3) 的冲突是重要发现**：jojowiki 上该条目出现两次（分列于 ACT1/ACT2 之后与后段），数值不同。这属于**同一形态在源内的重复登记**，需按形态链消解。

### 结论
34 处冲突中，约 30 处属「表示法差异」（可归一化），**4–5 处属真冲突**（需人工确认并记入 `stat_conflicts`）。真冲突比例约 3%，与立项书预估的 8–12% 冲突率有差距，需在评测报告中如实修正。

## 7. 编码陷阱

`topologytomato/jojostandstatsv2.csv` **不是 UTF-8**：

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xa0 at position 1886
```

`0xa0` 是不间断空格（NBSP），与 jojowiki 的 `Range: 2 m (6.6 ft)` 中的空格是同一字符。

**处理**：读取时按 `utf-8 → utf-8-sig → latin-1` 顺序尝试回退（实测该文件落到 latin-1）。
