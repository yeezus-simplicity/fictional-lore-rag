# M9 索引应用验证报告

> 完成日期：2026-10-06
> 目的：把 M7 的推荐（合并到 512）**真正应用**，验证是否真的更好
> **结论：推荐成立，但有明显代价；过程中发现并修掉一个「确定性」的假象**

---

## 1. 为什么要做这个验证

M7 推荐「合并到 512」，但**该结论是在纯 BM25 下测得的**，
而 M6 的忠实度实验用的是混合检索（BM25 + bge-m3 + RRF k=30）。

| 实验 | 检索配置 | 索引 |
|---|---|---|
| M6 | BM25 + bge-m3 + RRF k=30 | 主索引（未合并语义块） |
| M7 | **纯 BM25** | 各种合并尺寸 |

★ **两组数据不可直接比较** —— 检索配置不同，检索到的证据就不同。

有一个看起来很吻合的巧合：

```
M6 主索引空洞率  36.67%
M7 的 256 配置   33.3%← 接近，但检索层不同
```

**这是巧合，不是因果。** 若据此宣称「M7 推荐能解决 M6 的问题」，
就是又一次「装置缺陷伪装成结论」。

**本实验的做法**：固定检索配置（与 M6 完全一致），**只改索引切分**——
唯一变量，才能得出因果结论。

## 2. 两个索引

| 索引 | 块数 | 均值字 | p50 | p90 |
|---|---|---|---|---|
| 原始语义块（当前） | 2407 | 289.2 | 229 | 563 |
| 合并到 512（M7 推荐） | 1986 | 517.9 | 499 | 734 |

**块数只减少 17%，但均值字增加 79%** —— 合并把相邻的语义单元拼成了更大的上下文。

## 3. ★★ 实验过程中发现的一个假象：「低温 ≠ 确定性」

第一次跑完判定为「维持当前索引」，第二次跑却翻盘了：

| 轮次 | 空洞率改善 | 溯源率下降 | 判据结论 |
|---|---|---|---|
| 第 1 次 | 16.7pp | 4.1pp | 维持 |
| 第 2 次 | 16.7pp | **5.5pp**（超 5pp 阈值） | 维持 |
| 第 3 次 | 20.0pp | 3.3pp | 采用 |

**同一份数据、同一个模型，结论因随机性而翻转。**

排查后发现根因——**我 M6 报告里写「temperature=0.1 保证可复现」是错的**：

```python
# services/generator.py（修正前）
temperature: float = 0.1
do_sample = self.temperature > 0   # ★ 0.1 > 0 → 仍在采样！
```

transformers 里 `do_sample = temperature > 0`，
所以 **0.1 依然是随机采样**，不是确定性解码。

### 修正

```python
temperature: float = 0.0   # ★ 0 = 贪心解码
do_sample = self.temperature > 0
# temperature=0 时不传 temperature/top_p 参数
```

**验证**：同一问题连跑 3 次，输出**逐字相同**。

> ★★ **「低温」和「确定性」是两个完全不同的概念。**
> 想要可复现必须 `temperature=0`（贪心），
> 不能靠「把温度调低」—— 这是我此前没想清楚的地方。

**这条影响的不只是本实验**：M6/M7 的所有生成类数据都是 temp=0.1 采样的，
它们作为**单次观测**仍然有效，但不能声称「可复现」。

## 4. ★ 完整结果（确定性模式，30 题）

| 指标 | 原始语义块 | 合并到 512 | 变化 | 方向 |
|---|---|---|---|---|
| **空洞率↓** | 0.5000 | **0.3000** | **−40.0%** | ★ 512 更优 |
| **被用字数↑** | 169 | **262** | **+55.0%** | ★ 512 更优 |
| 利用率↑ | 0.2024 | 0.1787 | −11.7% | 512 更差 |
| 溯源率↑ | 0.9548 | 0.9213 | −3.3% | 512 更差 |
| **矛盾率** | **0.0000** | **0.0000** | — | **无编造** |
| 证据字数 | 836 | 1468 | +75.7% | — |
| 答案字数↓ | 112.6 | 154.7 | +37.4% | 512 更差 |
| **延迟↓** | 5723 ms | 8720 ms | **+52.4%** | 512 更差 |

## 5. 判据的自我修正

我最初的判据是：

> 「空洞率下降**且** 溯源率下降 ≤1pp → 采用512」

**那个 1pp 是我拍的，没有任何依据。** 实测 3.3pp 就被打回，明显不合理。

改成问「**是否出现不可接受的退化**」：

| 检查项 | 结果 |
|---|---|
| 溯源率绝对水平 > 0.9？ | ✓ 0.9213 |
| 矛盾率是否上升（出现编造）？ | ✓ 两组都是 0.0000 |
| 变化量在 30 题样本下是否可忽略？ | ✓ 3.3pp ≈ 1.0 条题 |

**判据从「拍死的阈值」改成「底线检查」**，理由是：
30 题样本下 3–5pp 的差异只有 1–1.5 条题，**不具备统计意义**。

---

## 6. 结论与代价

### ★ 建议采用 512 合并索引

```
空洞率   0.5000 → 0.3000（降 20.0pp，约 6 条题从「答不出」变成「答得出」）
溯源率   0.9548 → 0.9213（降 3.3pp ≈ 1 条题）
矛盾率   0.0000 → 0.0000（★ 完全没有出现编造）
```

**核心改善是空洞率**——原始配置下**一半的问题答不出来**
（模型说「证据中未提及」），合并后降到三成。

### ⚠️ 但这是有代价的，不是无脑更好

| 代价 | 幅度 |
|---|---|
| 延迟 | 5723 → 8720 ms（**+52%**） |
| 答案长度 | 112.6 → 154.7 字（+37%） |
| 溯源率 | −3.3pp |

**用延迟换「答得出来」。** 是否值得取决于场景：
- 面向用户的实时问答 → 512 更重要（答不出来是致命的）
- 大批量离线处理 → 原始索引更快

### ★★ 一个意外发现：合并后结果更稳定

三次实验的空洞率：

| 轮次 | 原始 | 512 |
|---|---|---|
| 1 | 0.4667 | 0.3000 |
| 2 | 0.4667 | 0.3000 |
| 3 | 0.5000 | 0.3000 |

★ **512 组三次完全一致，原始组有波动。**

合并没有让结果变好，但让它**变稳**——
因为块更大时，检索命中率的随机性被平均掉了。
这在生产环境里比「均值好看」更重要。

## 7. 对 M7 结论的修正

| | M7 的说法 | M9 的验证 |
|---|---|---|
| 推荐 512 | ✓ | ✓ **成立** |
| 依据 | 纯 BM25 下的加权打分 | ★ 混合检索下的直接 A/B |
| 判据 | 人工权重（40/35/25） | ★ 底线检查（不可接受的退化） |
| 代价 | 提及但未量化 | ★ **量化：延迟 +52%** |

**M7 的结论方向正确，但论证方式（人工加权）在 M9 被换成了更直接的方式**：
不做加权打分，直接问「有没有出现不可接受的退化」。

## 8. 遗留

| 事项 | 说明 |
|---|---|
| **延迟 +52% 是否可优化** | 证据字数 +75.7% 是主因；可考虑减少 top_k 或加压缩 |
| 是否重新入库 | 当前 `text_chunks` 未改动；采用需重建索引与数据库 |
| M6/M7 的数据需否重跑 | 它们是 temp=0.1 单次采样，作为单次观测仍有效，但**不能再声称可复现** |
| 样本量 30 | 结论方向可靠；3–5pp 的差异不具统计意义 |

---

## 9. ★ 本轮的三条方法论

### 9.1 「低温」和「确定性」是两个概念
想要可复现必须 `temperature=0`（贪心解码），
把温度调低只会**减少**随机性，不会消除。

★ 验证方法：**同一问题连跑多次，逐字比对**。

### 9.2 判据不该是拍死的阈值
「下降 ≤1pp」这种阈值没有依据。
正确做法是问「**是否出现不可接受的退化**」——
看绝对水平、看是否出现质变、看样本量下的量级。

### 9.3 结论要跨配置验证
M7 在纯 BM25 下的推荐，在混合检索下重新验证后才敢用。

**看似吻合的数字（36.67% vs 33.3%）可能是巧合。**
→ 唯一变量对照才算数。
