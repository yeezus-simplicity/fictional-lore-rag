### 详情页结构（实测，探查结论修正）

原以为正文由 JS 动态加载（37 个 `<p>` 全空），**这个判断是错的**。实际结构：

```html
<h3>User</h3><div>Jotaro Kujo</div>          ← 标量字段，有内容
<td class="pi-data-value" data-source="destpower">A</td>  ← 形态数值
```

- **标量字段**：`h3 + div` 相邻对（`User` / `Type` / `Origin` / `Awakening` / `Manga Debut` 等）
- **形态数值组**：`data-source` 属性配对，**同一 source 出现多次 = 不同形态**

> 这是本阶段最重要的发现，见下一节。

## 3. ★ 关键发现：主表的「重复登记」是形态未消解

主表有 3 组同名多行登记，V6 判为 WARN。详情页揭示了真相：

| 替身 | 主表登记 | 详情页形态数 |
| --- | --- | --- |
| Star Platinum | 2 次 | **3 个形态** |
| Killer Queen | 2 次 | 1 个（但数值差异大） |
| Echoes (ACT3) | 2 次 | **4 个形态** |

Star Platinum 详情页的 3 组数值：

```
form_0: PWR=A SPD=A RNG=C STA=A PRC=A DEV=A        ← 基础
form_1: PWR=A SPD=A RNG=C STA=A PRC=A DEV=Complete  ← The World
form_2: PWR=A SPD=A RNG=C STA=E PRC=A DEV=C        ← 觉醒后
```

**结论**：主表把同一替身的不同形态压成了多行，造成"看起来重复"。这不是脏数据，是**数据模型的正确表达**。已通过 `stand_forms` 表 + `form_chain` 消解。

`Echoes (ACT1/2/3)` 三个名字实际都指向同一个 `Echoes` 页面（4 个形态），去重后正确合并。

### ★ 值得关注的系统性偏差

**Tusk 四形态射程系统性差一档**：

| 形态 | 主源(jojowiki) | 镜像 A | 镜像 B |
| --- | --- | --- | --- |
| Tusk ACT1 | E | D | D |
| Tusk ACT2 | D | B | B |
| Tusk ACT3 | D | B | B |
| Tusk ACT4 | C | A | A |

**两个独立镜像完全一致地与主源差一档**，这不太可能是巧合——可能是镜像源的数据录入问题，也可能是主源采用了不同的射程标准。

> 这是 D5（冲突消解）实验的绝佳素材：**冲突不总是"某一方错了"，可能是双方采用了不同标准**。需要在技术文档中论证消解策略的选择依据。

### 消解策略

统一 `prefer_primary`（采 jojowiki），但**全部冲突落表不覆盖**。理由：
- 主源是唯一提供能力描述与形态链的源
- 主表的异常值保留原文（`*_raw`），可追溯

## 6. 修复的 Bug

### 6.1 `normalize()` 剥离尾随括号（M1-2 已修，此处补充影响）

条件值说明 `Range: 2 m (6.6 ft)` 被截断为 `Range: 2 m (6.6 ft`。已拆分「ID 生成的激进清洗」与「字面量归一化」两条路径。

### 6.2 URL 括号导致 404（本阶段新发现）

```
Echoes_(ACT1)  →  404
Echoes_ACT1→  200   ✅
```

`urllib.parse.quote(safe="_()!,'")` 保留了括号导致 404。已实现 `_url_variants()`：原名 → 括号转下划线 → 去括号，三级回退。

### 6.3 空字符串语义错误（本阶段新发现）

CSV 中的 `''` 被 `encode_stat` 归为 `EMPTY_SLOT`，产生 153 个假冲突。实际上 `''` 表示「该源根本没有此记录」，语义应是 `NOT_APPLICABLE`。

### 6.4 跨源字面量表不完整（本阶段新发现）

实测发现镜像源使用了主源没有的字面量：

| 字面量 | 归一类别 |
| --- | --- |
| `unknown` | `UNKNOWN` |
| `Infi` / `infinite` | `INFINITE` |
| `situational` | `CONDITIONAL_NO_BASE` |

已扩充 `encode.py` 的四组常量表。**这是"规范必须用真实数据迭代"的又一例证**——M1-1 只见到主源字面量，遗漏了镜像源的表达方式。

### 6.5 缓存读入类型不一致

`details.json` 读入是 dict，`merge()` 期望 `DetailPage`。已加 `_as_detail()` 适配层。

### 关于 `ability_desc` 的说明

这是原计划 M1 子项 4 的目标，**但实测发现无法达成**：详情页正文段落（能力描述、招式列表）全部为空（`<p>` 节点 37 个，`text_content()` 长度 0），内容由 JavaScript 动态加载。静态 HTML 只能拿到 infobox 的标量字段与数值。

**影响**：D1（切块策略实验）缺少长文本语料。

**替代方案**（待定）：
1. 用 Playwright 渲染页面后再抓（引入浏览器依赖）
2. 改用其他源提供描述文本
3. M1 先做结构化部分，D1 推迟到有语料时
